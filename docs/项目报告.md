# 《合成大派蒙》课程项目报告

> 依据截至 2026-10-21 的真实对话、项目文件与测试记录整理。用户已确认当前版本整体通过人工验收；逐项设备、耗时和截图未提供，不补造。课程群尚未提供可核实的提交截止时间。

## 1. 项目概况与功能

本项目面向课程演示和单人本地游玩。玩家在网页棋盘上横向选择投放位置，1～3 级角色以等概率进入投放队列。两个同级角色碰撞会合成高一级，目标等级为 `L` 时加 `2^L` 分；第 8 级为终级，不再合成。新投放角色有 2 秒越线宽限，之后持续越过警戒线 3 秒才结束。结束后可重新开始。

界面提供开始提示、分数、下一角色预览、短虚线投放列提示、八级角色图鉴、失败结果、静音开关及投放/合成/失败反馈。八张透明 PNG 是本项目通过图片生成工具制作并处理的原创演示角色图，不是《原神》官方派蒙图片。每级按其姿势配置多个 Matter 圆形或矩形子体，构成不同轮廓的复合碰撞体。

运行效果可查看 [桌面界面](第11轮_桌面界面.png)、[窄窗口界面](第11轮_窄窗口界面.png)、[八级素材总览](第10轮_八级素材总览.png)及[碰撞核对总览](第10轮_八级碰撞核对总览.png)。这些截图取自较早轮次；用户已确认当前版本，但未单独提供第 14～16 轮调整后的截图。

## 2. 需求分析

项目只做本地单人游戏，不做账号、排行榜、联网对战或服务器。核心需求包括：可启动网页、鼠标/触屏投放、重力与容器碰撞、八级合成、计分、失败判定、重新开始、可识别的素材与反馈。完整验收条件和不规则碰撞风险见 [需求分析](需求分析.md)。

固定规则在开发前由项目负责人接受；后续新增或修改的界面、音效和尺寸要求均记录为真实迭代，没有倒写成最初需求。项目负责人于 2026-10-21 明确说明项目为个人、非商业用途并要求将《原神》BGM 文件提交到仓库；曲目来源与权利标识见[音乐素材清单](音乐素材清单.md)。游戏不依赖在线音乐服务。

## 3. 系统分析与设计

| 主要对象 | 职责 |
| --- | --- |
| `GameScene` | 创建棋盘与物理世界，组织投放、合成、失败、重开及界面反馈。 |
| `DropController` | 管理鼠标/触屏位置、等级队列、冷却和投放预览。 |
| `LevelCatalog` | 保存八级尺寸、纹理键与独立轮廓零件；限定 1～3 级随机池。 |
| `Piece` / `CompoundBody` | 表示在场角色，并根据等级零件构造 Matter 复合刚体。 |
| `MergeResolver` | 对同级接触排队、去重并给出合成目标。 |
| `GameSession` | 保存分数、结束状态和每枚角色的越线计时。 |

具体关系图、状态所有权和流程分别见 [系统分析](系统分析.md)、[系统设计](系统设计.md)。采用 TypeScript + Phaser 3.90 + Matter.js；Vite 用于开发和构建，esbuild 生成可直接打开的离线脚本。项目目录、命令及文件说明见 [游戏 README](../game/README.md)。

## 4. 与 Coding Agent 的分步开发过程

项目负责人先提出固定规则，再按可验收子任务推进。以下引文均来自[开发过程记录](开发过程记录.md)，各轮完整原始提示词和实际产出可在该文件查阅。

| 阶段 | 代表性自然语言要求 | Agent 实际产出与检查 |
| --- | --- | --- |
| 分析与计划（第 1～4 轮） | “本轮不要创建程序代码”“避免为了‘面向对象’而人为增加空类” | 需求、对象、设计与七任务开发计划；未提前实现程序。 |
| 基础运行（第 5～6 轮） | “创建最小可运行页面和游戏画布”“只增加单人投放和基础物理” | Vite 页面、Phaser 棋盘、鼠标/触屏投放、容器边界和重力。 |
| 核心规则（第 7～8 轮） | “同级碰撞合成及计分”“增加顶部警戒线、持续越线后失败” | 八级配置、合成去重、计分、2 秒宽限、3 秒判负与重开；编写规则测试。 |
| 碰撞与素材（第 9～10 轮） | “不能只换贴图、仍统一用圆形碰撞”“八级角色姿势和轮廓要明显不同” | 每级独立复合刚体、八张原创透明 PNG、素材来源及碰撞核对记录。 |
| 界面与音效（第 11～13 轮） | “完善开始提示、当前分数、下一角色预览”“只在第一次放置时显示投放”“添加 BGM” | 响应式界面、原创短音、静音、本地可选 BGM；移除玩家端碰撞调试入口。 |
| 反馈细化（第 14～16 轮） | “短虚线”“角色列表”“去掉‘可直接投放’”“第6、7级大小差距较小” | 投放列提示、八级图鉴与分级尺寸调整；相应代码、README 和验收预期同步更新。 |

这一过程体现“给需求 → Agent 编码和运行检查 → 用户反馈 → 定向修改”的课程要求。第 8 轮后曾出现直接打开 `game/index.html` 时页面只显示文字的真实问题；用户提供截图后，Agent 增加离线脚本与样式构建，保留了[问题记录](开发过程记录.md)及对应命令结果。第 11 轮后用户要求“投放”浮字只出现一次，Agent 用局内状态控制并在重开时重置。后续图鉴文字和尺寸调整同样来自用户真实反馈。

## 5. 测试与人工反馈

2026-10-21 在 `game/` 执行 `npm test`：**12 项通过、0 项失败**，涵盖 PNG 格式和区别、八级复合体落地/旋转/堆叠、1～3 级随机映射、合成去重与计分、越线和重开规则。`npm run build` 的 TypeScript 检查、Vite 产物及离线脚本构建均成功。Vite 报告 Phaser 主包超过 500 kB 的非阻断体积提示。

项目负责人在对话中明确确认过需求分析、系统分析、系统设计、开发计划、基础投放、合成分数、核心循环、复合碰撞、素材玩法及界面音效等轮次，并于 2026-10-21 确认**当前版本已全部人工验收**。第 12 轮[端到端人工验收表](第12轮_端到端人工验收表.md)据此记录总体通过；逐项操作顺序、设备、测量值和截图没有提供。已有 AI 浏览器检查和截图在过程记录中单列，不被写作用户逐项实测数据。

## 6. 交付与限制

仓库包含源码、可直接打开的离线脚本、八级原创角色图、需求/设计/计划/过程记录和本报告。`node_modules/`、构建缓存与 `dist/` 不提交，可通过 `npm install`、`npm run build` 重建。
