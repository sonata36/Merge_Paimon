# 《合成大派蒙》分步开发计划（第 4 轮）

> 本文保留七个任务在第 4 轮制定时的原始边界。第 5 节记录后续已实施的最终版增量；这些增量现已纳入课程项目最终交付，不再视为作业外自拓展。

> 本计划依据已验收的需求分析、系统分析和系统设计，把对话稿第 5～11 轮对应为七个独立开发任务。以下均为**未来交付和验收标准**，不是已完成结果。本轮不创建 `game/` 或程序代码。

## 1. 执行与记录规则

- 每次只向 Coding Agent 交付当前任务；Agent 报告实际修改、运行命令和结果，给出手工验收步骤。
- 我在对话中反馈“通过”或问题复现信息后，由 Agent 如实填写 `docs/开发过程记录.md` 的人工验收栏。未获验收，不进入下一任务。
- 如果本任务验收失败，先在**同一任务**内反馈并修复，再复测；不把尚未完成的功能挪到后续任务，也不为了报告编造缺陷。
- 每轮保存原始提示词、AI 输出摘要、实际文件变化、终端结果和真实截图。构建通过只能证明代码可构建，不能代替人工玩法验收。
- 第 5 轮开始才创建 `game/`；核心玩法先用占位形状完成，角色 PNG 与音效安排在其后。

## 3. 七个开发任务

### T1｜第 5 轮：初始化项目与最小页面

- **输入**：`docs/需求分析.md`、`docs/系统分析.md`、`docs/系统设计.md`；当前工作目录和系统设计中的版本基线。
- **AI 交付**：创建 `game/`，采用 TypeScript + Phaser 3.90.0 + Phaser 内置 Matter + Vite 7.x；生成启动入口、单场景、空棋盘/边界的可见页面及 `game/README.md`。记录 Node、npm 和实际依赖版本及锁文件。此轮不实现投放、合成或失败。
- **完成标准**：依 README 安装并启动后可看见页面和画布；类型检查及构建成功；终端结果真实记录。若环境不满足要求，先解决环境问题再验收本任务。
- **人工测试**：①照 README 从 `game/` 启动；②打开本地页面，确认棋盘/画布可见、尺寸合理；③刷新页面检查无明显空白或错误；④查看浏览器控制台与 Agent 的构建输出。
- **依赖与边界**：无程序任务前置；只建立后续可扩展的框架，不把 T2～T7 功能提前合并进来。
- **建议证据**：原始提示词、依赖版本/构建结果截图、页面截图、README 的启动步骤。

### T2｜第 6 轮：投放、重力和边界

- **输入**：验收通过的 T1 项目；需求 FR-02、FR-03；系统分析中的 `DropController`、`Piece`、`GameScene` 职责。
- **AI 交付**：占位角色的横向预览；鼠标/触屏定位与释放；投放冷却和左右位置限制；Matter 重力、底板和侧壁碰撞。可先用一个占位等级验证物理，不在此轮做等级合成或计分。
- **完成标准**：角色从所选位置下落、碰撞、堆叠，不穿越底部或侧壁；快速重复输入不会生成异常数量的角色；基础玩法在刷新后仍可运行。
- **人工测试**：①分别在棋盘左、中、右投放；②连续投放数枚，观察落地和相互碰撞；③快速点击/触摸，确认冷却有效；④把指针移出棋盘边缘再投放，确认出生点仍在合法范围。
- **依赖与边界**：T1 通过；本轮不要求同级合成、分数、失败或正式角色图片。
- **建议证据**：不同投放位置和堆叠截图、鼠标与触屏操作记录、Agent 实际检查结果。

### T3｜第 7 轮：八级配置、同级合成和分数

- **输入**：验收通过的 T2；需求 FR-02、FR-04、FR-05；系统设计的 `LevelCatalog`、`MergeResolver`、`GameSession` 数据流。
- **AI 交付**：八级颜色/数字可辨的占位角色；直接投放仅 1～3 级且各 `1/3`；同级且低于 8 级才合成；合成到目标等级 `L` 加 `2^L` 分；碰撞事件去重及安全结算。8 级终止合成。
- **完成标准**：同级升一级、异级不变、8+8 不合成；一次合成只移除两枚旧角色、创建一枚新角色并加一次分；随机逻辑可用受控输入核对等概率规则。显示分数与内部结算一致。
- **人工测试**：①确认多次直接投放只出现 1～3 级；②观察一次 1+1→2，分数增加 4；③让异级相接，确认不合成；④按 Agent 给出的可复现方式核对 7+7→8、8+8 及连续碰撞去重。
- **依赖与边界**：T2 通过；继续使用占位外观，本轮不要求失败结束和不规则碰撞体。
- **建议证据**：合成前后与分数截图、随机规则检查记录、终级和连续碰撞的真实测试结果。

### T4｜第 8 轮：失败判定、结束与重开

- **输入**：验收通过的 T3；需求 FR-07、FR-08；系统设计中的本局状态和物理轮廓越线规则。
- **AI 交付**：可见失败警戒线；新投放角色释放后 2 秒宽限；宽限后任一角色连续越线 3 秒结束；回线下重置计时。结束后停投、显示最终分数、可重开并清理上一局物体/队列/监听/计时。
- **完成标准**：下落瞬间不误判；越线不足 3 秒又回落不失败；真正堆满会结束；结束后不能继续投放；多次重开没有旧局残留、重复计分或重复事件。
- **人工测试**：①正常投放观察警戒线附近的 2 秒宽限；②按 Agent 提供的可复现场景验证短暂越线与持续越线；③失败后尝试投放，确认被阻止；④连续重开两次并再次合成，确认分数从 0 开始且只结算一次。
- **依赖与边界**：T3 通过；这一轮完成**基础可游玩闭环**，仍允许占位图和简易界面。
- **建议证据**：警戒线、失败画面、重开前后截图及计时测试记录。

### T5｜第 9 轮：不规则复合碰撞体

- **输入**：验收通过的 T4；需求 FR-06；系统设计的多部件物理体、等级配置和调试覆盖层方案。
- **AI 交付**：先实现并验证至少两种明显不同的复合轮廓，再补齐八级独立配置；单个角色的图像与物理体共同平移/旋转；提供碰撞体调试显示开关，正常游玩默认关闭。
- **完成标准**：八级均有独立非圆形复合碰撞体；至少两级在调试图和实际滚动/堆叠中差异显著；仍能正常合成、失败与重开；约 50 个角色持续操作 30 秒时保持可响应。性能判断以实际测试记录为准。
- **人工测试**：①开启调试视图比较紧凑型与横向展开型；②各投放数枚，观察落地、旋转、堆叠是否不同；③逐级检查碰撞配置不是同一个圆；④关闭调试后测试合成、失败和重开；⑤按可复现方式观察约 50 个角色时的响应。
- **依赖与边界**：T4 通过；这一轮仍可使用占位图，正式 PNG 校准由 T6 完成。不能把“不规则贴图”当作“不规则碰撞”验收。
- **建议证据**：开启/关闭调试的截图、两种形状堆叠差异、八级配置清单及性能观察记录。

### T6｜第 10 轮：八张角色素材制作与接入

- **输入**：验收通过的 T5；现有本地素材检查结果；系统设计的统一画布、视觉中心和等级配置方案。
- **AI 交付**：制作或接入八张表情包风格的透明 PNG，按 `lv1.png`～`lv8.png` 对应等级；在 `docs/素材清单.md` 记录来源、处理方式与使用范围；替换占位纹理并按真实可见主体校准八级碰撞体。缺图时保留占位回退和明确提示。
- **完成标准**：八级图均实际存在并能加载，姿势/轮廓可辨；图片与碰撞体没有明显边距或重心错位；玩法规则、合成分数和失败判定不因换图而改变。未做齐八张时继续在本任务中完成，不进入 T7。
- **人工测试**：①逐级查看角色贴图与等级；②开启调试图核对可见主体与物理轮廓；③选几级测试滚动、堆叠和合成；④按 Agent 指引临时模拟缺图，确认有提示或回退；⑤核对素材清单内容。
- **依赖与边界**：T5 通过；不把未核实来源的网络候选图当成已授权/已导入素材，不把占位图称为正式角色图。
- **建议证据**：八级素材总览、碰撞校准截图、素材清单、接入前后对比与缺图行为记录。

### T7｜第 11 轮：界面、反馈与原创音效

- **输入**：验收通过的 T6；需求 FR-01、FR-09、FR-10；已可运行的完整玩法。
- **AI 交付**：完善开始提示、当前分数、下一角色预览、失败/重开界面与较窄窗口布局；制作或程序合成原创的投放、合成、失败音效，加入静音开关，并处理浏览器自动播放限制。
- **完成标准**：界面状态与实际一局一致；鼠标/触屏均能操作；三类音效及静音开关有效，音效加载/播放失败不影响玩法；构建成功，README 说明操作方式。
- **人工测试**：①从开始到失败再重开完整游玩一次；②检查分数、下一角色及状态文字；③分别触发三类音效并开关静音；④缩窄窗口确认按钮与棋盘可用；⑤检查控制台有无影响操作的错误。
- **依赖与边界**：T6 通过；不增加登录、联网、排行榜、背景音乐或角色配音。完成后进入第 12 轮完整人工测试，而不是直接宣称项目最终验收。
- **建议证据**：开始/进行中/失败三种界面截图、窄窗口截图、音效测试记录、构建结果。

## 4. 任务完成后的报告衔接

七项开发任务完成后，按对话稿第 12 轮生成端到端人工验收表并实际测试；第 13 轮只处理真实发现的问题；第 14 轮依据已有对话、终端输出、截图和复测记录整理电子版报告。不存在真实缺陷时如实说明，不人为制造“修复过程”。

> 2026-10-20 补充：本计划保留原七任务的历史顺序。后续用户明确要求玩家页面移除碰撞体显示并加入《原神》BGM；当前交付范围以 `docs/需求分析.md` 第 10 节和 `docs/音乐素材清单.md` 为准。
