# 《合成大派蒙》需求分析（第 1 轮）

## 1. 目标与边界

本项目是供课程展示的**本地单人网页合成游戏**。玩家在棋盘顶部选择位置投放角色，让同等级角色接触、合成升级并获得分数；角色堆叠超过警戒线会结束本局。八级角色使用表情包风格的派蒙造型，**不规则复合碰撞体**会影响滚动和堆叠，是区别于普通圆形合成游戏的核心特色。

目标用户是课程教师、同学和体验小游戏的玩家。典型场景是：按 README 在电脑上启动游戏，阅读玩法提示，持续投放和合成，观察得分与下一角色，失败后查看成绩并重新开始。游戏无需登录、联网服务或个人数据。

约束：程序使用 TypeScript、Phaser 和 Matter.js，位于 `game/`；分析与测试材料位于 `docs/`。先用占位形状验证玩法，再制作或接入八张透明 PNG。素材尚未进入本地项目，需求文档不把前期聊天中的候选图视为已交付素材。

## 2. 角色与状态

- **玩家**：使用鼠标或触屏移动投放位置、释放角色，查看分数、预览和失败状态，控制音效并重新开始。
- **游戏状态**：开始前、进行中、已结束。开始前提供玩法提示；进行中允许投放；已结束停止投放，显示本局分数并允许重开。
- **角色等级**：1～8 级。只有 1～3 级能直接作为待投放角色；4～8 级通过合成产生。8 级是终级。

## 3. 功能需求与验收条件

| 编号 | 功能需求 | 可验收条件 |
| --- | --- | --- |
| FR-01 | 玩家可以开始一局游戏，看到投放区域、棋盘边界、失败警戒线和简短玩法提示。 | 按 README 启动并打开页面后，画面可见；开始后进入可投放状态；按钮和文字可辨认。 |
| FR-02 | 游戏开始时准备第一枚待投放角色。待投放等级仅从 1、2、3 级独立等概率抽取，各为 `1/3`；投放后继续生成待投放角色，并显示下一角色预览。 | 多轮投放不会出现 4～8 级直接生成；随机规则可用受控随机输入或等价方法核对三个结果各占 `1/3`，不能仅凭少量局数的频数判断概率；预览与实际待投放等级一致。 |
| FR-03 | 玩家可用鼠标或触屏在棋盘顶部调整横向投放位置并释放角色；投放位置受左右边界限制。角色受重力影响，与底部、边界及其他角色发生碰撞和堆叠。 | 在左、中、右位置投放均有效；角色不穿透棋盘边界；连续快速操作不会产生不受控的重复投放；鼠标和触屏均可完成基本操作。 |
| FR-04 | 两个相同且低于 8 级的角色有效接触时，只结算一次合成：移除原两枚，在合理位置生成下一级角色。不同等级不合成；两个 8 级角色不合成。 | 可验证 1+1→2、其他相邻等级的同级合成及 7+7→8；异级接触不变；8+8 不合成；连续碰撞时不出现重复生成、残留角色或重复结算。 |
| FR-05 | 每次合成按**生成后的目标等级** `L` 加 `2^L` 分。例如 1+1→2 加 4 分、7+7→8 加 256 分。投放和普通碰撞不加分。 | 每次合成后分数变化与公式一致且只加一次；无合成时分数不变；显示分数与内部结算一致。 |
| FR-06 | 角色物理轮廓由该等级的多个简单形状组合而成，可随角色旋转；八级各有独立配置，不能统一使用圆形碰撞体。提供可开关的碰撞体调试显示。 | 至少两种轮廓差异明显的角色在调试图和实际堆叠行为中体现差别；最终八级均有独立配置；碰撞体大体贴合对应贴图可见主体，不因细小装饰导致明显卡住或穿透。 |
| FR-07 | 棋盘上方有失败警戒线。**新投放**角色释放后的前 2 秒不参与越线失败计时；宽限期后，任一角色的物理轮廓持续越线 3 秒则结束本局，期间回到线下则重新计时。 | 新角色经过警戒线下落时不立即失败；持续越线不足 3 秒且回落不会失败；宽限期结束后持续越线达到 3 秒才结束；失败后无法继续投放。 |
| FR-08 | 失败时显示本局最终分数并提供重新开始。重开须清空旧角色、计时器、碰撞事件监听和上一局分数，重新准备待投放角色。 | 失败后点击重开，棋盘恢复初始状态、分数为 0、可正常投放；重复重开不出现旧角色、重复合成或重复音效。 |
| FR-09 | 页面显示当前分数、下一角色预览、开始/重开入口、玩法说明和音效开关；提供投放、合成、失败的原创简单音效。 | 游戏状态与界面信息一致；静音后无游戏音效但玩法正常；浏览器阻止自动播放时游戏仍能启动和操作。 |
| FR-10 | 最终接入八张透明 PNG，等级与文件一一对应；保存文件名、来源、制作/处理方式和使用范围。缺图时显示明确提示或占位图。 | 八级贴图可辨识、画布规格一致、无明显透明边距造成的视觉/碰撞错位；素材清单可查；故意移走一张图时游戏不静默崩溃。 |

## 4. 关键规则与边界情形

1. 合成计分以**一次成功合成**为单位。多对象同时接触时，同一角色同一时刻最多参与一次合成，避免事件重复触发。
2. 8 级角色继续受物理作用，可堆叠并触发失败判定，但不再合成，也不能直接随机投放。
3. 失败判定依据物理碰撞体越过警戒线，而非 PNG 透明画布的外框。合成后生成的角色也受警戒线规则约束；2 秒宽限仅针对新投放角色。
4. 任何可能引起分数、对象数量或游戏状态变化的操作，在已结束状态下都不能继续处理成新一局的结果。
5. 随机池的概率是规则，不保证短样本恰好三等分。实际验证应检查生成逻辑或使用受控随机输入。

## 5. 非功能要求

| 类别 | 要求与验证方式 |
| --- | --- |
| 可运行性 | 按 README 在普通桌面浏览器本地启动，完成“开始→投放→合成→失败→重开”的完整流程；不依赖账号或后台。 |
| 稳定性 | 重复投放、连续合成、失败和多次重开不崩溃；错误资源有提示。自动化检查和人工操作都只报告实际执行结果。 |
| 性能 | 常见桌面电脑上堆叠约 50 个角色并持续操作 30 秒时，游戏保持可响应、无明显长时间卡死；不规则碰撞体的形状数量和细节以稳定性为先。 |
| 可读性 | 主要模块、对象职责、等级配置与碰撞体配置清楚；至少提供一张与实际实现一致的对象关系或类图。 |
| 可展示性 | 能截取界面、合成前后、碰撞调试图、失败与重开的真实运行画面；保存逐轮 AI 对话和人工测试记录。 |

## 6. 素材与使用范围

- 八张角色图采用统一规格的透明 PNG、清晰可辨的表情包风格，八级姿势和外轮廓应明显不同；图像尺寸、物理尺寸及透明边距在接入时统一核查。
- 开发前期使用占位形状，最终素材由 Agent 制作，或从项目中已有且来源明确的素材接入。前期讨论链接展示的 ZIP 和网络候选图目前没有作为本地文件提供，不能声称已可用。
- 记录每张素材的文件名、来源、制作或处理方式、课程演示使用范围。项目先用于本地课程展示，不在本阶段公开发布。
- 音效为原创的简单投放、合成和失败音效；不做背景音乐与角色配音。

## 7. 不做的功能

不做登录注册、联网对战、云存档、排行榜、支付、后台管理、背景音乐、角色配音或公开发布流程。也不要求复杂关卡、商城或额外游戏模式。

## 8. 不规则碰撞体的主要风险

| 风险 | 影响 | 后续设计与验收关注点 |
| --- | --- | --- |
| 形状过细、部件过多 | 物理计算变慢，角色抖动或卡住。 | 用少量简单形状近似主体轮廓；检查约 50 个角色的可响应性。 |
| 碰撞体与贴图缩放或重心不一致 | 视觉上悬空、穿透，旋转不自然。 | 在调试模式逐级对照透明 PNG 的可见主体，检查落地、旋转和堆叠。 |
| 一次接触触发多个碰撞事件 | 同一对角色重复合成或重复计分。 | 设计一次性结算保护；验证连续碰撞和多角色接触。 |
| 删除旧物体、生成新物体的时序不当 | 角色残留、合成后再次错误碰撞，甚至物理引擎异常。 | 明确合成队列/结算时机，检查对象清理及新角色初始位置。 |
| 顶部宽幅角色旋转或刚合成时越线 | 失败判断误报或计时不一致。 | 以物理轮廓判定，逐帧/定时连续计时；测试 2 秒宽限及 3 秒持续规则。 |

## 9. 交付判定

项目最后需具备：可运行的程序与 README、八级角色图及来源清单、八级碰撞体配置和调试证据、需求/分析/设计文档、真实分轮对话记录、人工测试与真实问题修复记录、电子版项目报告。第 1 轮只交付本需求分析文档，不提前创建程序。

## 10. 后续用户确认的范围变更（2026-10-20）

本节保留第 1 轮原始验收基线，同时记录后续用户明确提出的变更；与上文冲突时，以本节为当前交付要求。

- 玩家页面移除“显示碰撞体”功能和按钮。八级独立复合碰撞配置保留；可用自动测试及开发期保存的调试证据核对。
- 增加《原神》曲目 **A Day in Mondstadt** 的本地 BGM。点击开始后播放并循环，失败时暂停，重开时恢复；静音按钮同时控制 BGM 与三种原创短音效。音频受浏览器用户手势限制时不得影响玩法。
- 因此，第 6、7 节原先的“不做背景音乐”和第 3 节 FR-06 中的“提供可开关的碰撞体调试显示”是**历史要求**，在当前玩家版本不再适用。音乐来源和使用范围见 `docs/音乐素材清单.md`。
