## 2. 最小可运行版的模块划分

| 模块/文件职责 | 对应分析对象 | 设计说明 |
| --- | --- | --- |
| 启动入口 | 无额外业务对象 | 创建 Phaser 游戏实例，配置 Matter、画布尺寸和场景。配置可集中，不在业务对象中重复。 |
| `GameScene` | 游戏场景 | Phaser 场景生命周期、静态边界、物理事件订阅、角色集合、界面/音效、调试视图及重开清理的协调者。分数与游戏状态只从 `GameSession` 读取。 |
| `DropController` | 投放控制 | 处理统一的指针输入（鼠标/触屏）、横向位置限制、投放冷却、当前与下一等级；1～3 级按各 `1/3` 生成。 |
| `Piece` | 角色实例 | 一枚活动角色的唯一 ID、等级、Matter Image/物理体引用与释放时间。合成新生角色标明不是“新投放”，不享受 2 秒宽限。 |
| `LevelCatalog` | 等级配置 | 八级静态数据：图片键、画面尺寸、复合碰撞体部件、外观/占位标识。素材路径及来源在独立清单记录；本模块不保存活动状态。 |
| `MergeResolver` | 合成判定 | 接收碰撞双方，核对同级且低于 8 级，锁定待合成 ID、生成待结算项；场景在物理回调结束后执行移除和生成。 |
| `GameSession` | 本局状态 | 统一保存开始前/进行中/已结束、总分、各角色越线持续起点；处理 `2^L` 得分、2 秒宽限和 3 秒持续越线。 |
| 物理体构造辅助函数 | `LevelCatalog` 的实现辅助 | 根据配置构造一个复合 Matter Body 并绑定图片对象，不建立新的业务类；用于八级角色与占位角色。 |

图像加载、界面绘制和音效播放最初由场景协调，必要时可拆为普通辅助函数；不额外建立空的管理类。实现若偏离已验收的六个主要职责单元，须在开发记录中说明原因。

## 4. 数据流与关键时序

### 4.1 一局的状态流

`开始前 → 进行中 → 已结束 → 重开后进行中`。`GameSession` 是状态和分数的唯一来源。开始和重开时总分为 0、越线计时为空；结束后忽略新的投放与合成请求。场景按状态刷新 UI，而不另存分数副本。

### 4.2 投放

`指针位置 → DropController 夹到棋盘内 → 读取当前等级 → GameScene 按 LevelCatalog 创建 Piece → Matter 世界中落下 → 更新当前/下一等级与预览`。预览只是显示状态，不具有物理体。位置限制依据该等级碰撞体的水平尺寸预留余量，避免宽角色出生时穿墙。鼠标和触屏共用 Phaser 指针事件，减少两套输入逻辑。

### 4.3 碰撞、合成、计分

`Matter collisionstart → GameScene 识别接触对 → MergeResolver 规范化复合体子部件到所属 Piece → 校验/锁定 ID → 待结算队列 → 本次物理回调结束后移除两枚旧 Piece → 创建高一级 Piece → GameSession 加 2^L 分 → 更新显示/音效`。

Phaser 3.90 的 Matter World 提供 `collisionstart` 及碰撞对列表；Matter 的复合体有父体与子部件，因此判定应归一到角色根物理体/唯一 ID。事件回调内只排队，不在遍历接触对时反复销毁/新建；同一 ID 处于待结算状态时拒绝再次入队。[Phaser Matter 碰撞事件说明](https://docs.phaser.io/phaser/concepts/physics/matter)、[Matter Body 文档](https://brm.io/matter-js/docs/classes/Body.html)

### 4.4 越线失败与重开

每次场景更新只检查当前活动角色的**物理体边界**，例如复合体整体 `bounds.min.y` 是否高于警戒线；不使用 PNG 画布外框。`GameSession` 依据释放时间跳过新投放角色的前 2 秒；之后为每个持续越线角色记录起点，满 3 秒转为已结束，回到线下立即清除该次计时。合成产生的角色不享受投放宽限。计时采用游戏更新时钟；暂停/失焦时避免仅靠真实墙上时间突然触发失败。

重开时场景注销旧事件监听、清除活动角色和物理体，`MergeResolver` 清空队列与锁定 ID，`GameSession` 清空分数/计时与结束状态，`DropController` 重置待投放与冷却。不要销毁之后仍需复用的 Matter World；场景生命周期内按注册位置成对注销事件。

## 5. 透明图片与不规则碰撞体

### 5.1 一份等级配置驱动画面和物理

每级记录：`level`、透明 PNG/占位纹理键、统一的逻辑显示尺寸、角色视觉中心，以及若干个相对视觉中心定义的碰撞子部件（圆形、矩形或简单凸多边形）。图片和碰撞体共用**同一逻辑尺寸与中心**。PNG 透明画布边距先统一，再校对贴图主体；不要把整张 512×512 透明画布直接当作碰撞范围。

每次创建角色时，按等级配置生成若干简单子形状，组成**一个**复合 Matter Body，再挂到一个 Matter Image 上。角色平移与旋转由同一物理体驱动图像。Phaser 3.90 的 Matter Image 支持 `setExistingBody`；其 `this.matter.bodies` 与 `this.matter.body` 可访问 Matter 的形状与刚体工厂。这里采用的是有官方 API 支撑的设计路径，具体参数仍须第 9 轮在实际代码中验证。[Phaser Matter Image](https://docs.phaser.io/api-documentation/3.90.0/class/physics-matter-image)、[Phaser setExistingBody](https://docs.phaser.io/api-documentation/3.90.0/namespace/physics-matter-components-setbody)、[Phaser MatterPhysics](https://docs.phaser.io/api-documentation/3.90.0/class/physics-matter-matterphysics)

### 5.2 凹轮廓和细小突出部位

用数个**可适度重叠的凸形子部件**近似头部、身体和明显伸出的手臂；凹陷位置保留在子部件之间。细发丝、衣摆尖角和极小装饰不进入碰撞体，以免抖动或挂住。优先让主体堆叠稳定，再调整贴合程度。Matter 文档说明凹多边形分解可能需要额外 `poly-decomp`，复杂轮廓还可能产生不理想形状；因此最小版不依赖自动描边/自动凹多边形分解，也不额外安装这项依赖。[Matter Bodies.fromVertices 文档](https://brm.io/matter-js/docs/classes/Bodies.html)、[Matter Body.setParts 文档](https://brm.io/matter-js/docs/classes/Body.html)

建议每级从少量部件起步，再根据第 9～10 轮调试结果调整。头大身小型、横向趴地型、双臂展开型应有明显不同的真实物理外形，而非统一圆形仅换贴图。贴图接入后逐级验证落地、旋转、堆叠、合成和碰撞边界，不在附着物理体后随意只缩放图片。

### 5.3 调试显示

在场景中提供一个仅用于开发/验收的开关。首次开启时通过 `this.matter.world.createDebugGraphic()` 建立覆盖层；切换 `drawDebug` 和覆盖层可见性以显示/隐藏物理轮廓，避免重复创建 Graphics。Phaser 3.90 API 明确提供 `createDebugGraphic`、`debugGraphic` 与 `drawDebug`。最终正常游玩默认关闭；第 9～10 轮截图时开启。[Phaser Matter World 3.90](https://docs.phaser.io/api-documentation/3.90.0/class/physics-matter-world)

## 6. 占位素材到正式素材的替换

1. 第 5～9 轮使用程序生成的八种可辨认占位纹理/形状；等级、画面尺寸和碰撞配置已走同一个 `LevelCatalog`，避免素材替换重写玩法。
2. 第 10 轮检查本地是否已有来源明确的角色图；如没有，制作八张统一画布的透明 PNG。为每张记录文件名、来源、处理方式和课程演示使用范围。
3. 将 `LevelCatalog` 的纹理键指向正式 PNG；保持等级 ID、合成和计分规则不变。按真实可见主体微调八级部件配置及视觉中心，并用调试覆盖层逐级验证。
4. 对加载失败的图片给出可见提示或回退占位纹理；不能静默让角色消失。音效缺失也不得阻止基础玩法。

## 8. 风险与降级方案

| 风险 | 首选处理 | 降级时仍须保留的要求 |
| --- | --- | --- |
| 复合体部件过多导致抖动或卡顿 | 减少部件、合并小装饰、调整摩擦/弹性，检查约 50 个角色连续操作。 | 每级仍需有独立且真实参与碰撞的非圆形配置；不能统一退回圆形。 |
| 贴图与物理体中心、缩放不一致 | 统一画布、视觉中心和逻辑尺寸，调试图逐级校对。 | 保留真实碰撞差异；不能只靠图片制造不规则外观。 |
| 自动处理凹多边形失败 | 使用手工定义的少量凸形复合部件。 | 无需自动描边，但整体堆叠须稳定且明显贴合主体。 |
| 正式角色图未能及时完成或加载失败 | 保留占位纹理、清楚显示缺项并记录素材状态。 | 玩法可运行；最终交付仍须补齐八张透明 PNG。 |
| 浏览器限制自动播放音效 | 在首次用户交互后播放；音效失败时继续游戏。 | 投放、合成、失败和静音开关的设计仍保留。 |
| 实际版本出现类型或 API 差异 | 核对固定版本的官方 API，调整调用并保留安装/构建记录。 | 不未经记录切换 Phaser 4、Arcade Physics 或另一套技术栈。 |
